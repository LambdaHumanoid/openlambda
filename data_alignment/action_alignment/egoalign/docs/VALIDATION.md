## Release-entry regression coverage

Negative tests cover overlapping or symlinked input/output paths, invalid inputs
with `--overwrite`, missing/extra/swapped camera files or references, unsupported
replay concurrency, subprocess failure/interruption, and caller-relative CLI
paths. The sample validator checks each camera against both metadata and the
source export before comparing hashes. The bundled replay driver accepts one
worker; custom drivers must explicitly declare a larger supported capacity.
Captured body, hand and token arrays must have exact frame counts and widths
(29/7/7/64); missing, non-finite or non-real payloads are rejected before any
numeric comparison. Tests include singleton dimensions that NumPy could broadcast.

These are non-motion checks. They do not change alignment parameters, runtime
patches or sample data, and do not replace fresh physics qualification. The
saved 1006-frame sample is also rechecked against its original control capture.

## Recheck your checkout

```bash
python -m pytest -q
python tools/check_cli.py
python tools/audit_source.py
```

The audit checks source packaging, manifested sample hashes and publication
boundaries; it is not a complete security audit. Follow the
[example recipe](../examples/README.md) for a fresh physics replay and validate
the final export against its selected replay with `python -m egoalign.verify_sample`.
Keep the command logs, resolved configuration, source/asset hashes and telemetry
generated by your run. Never substitute offline staging tokens for final labels.

The packaging audit inspects hidden source files and rejects symlinks, including
hidden ones. It reports explicit local exclusions: root `.git` metadata and
`.venv`, plus `__pycache__`, `.pytest_cache`, `.mypy_cache` and `.ruff_cache`
directories. Excluded content is not audited and must not be distributed.
